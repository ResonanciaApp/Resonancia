Causa secundaria — env vars que interfieren con tunnel
El dev script del workflow incluye:

EXPO_PACKAGER_PROXY_URL=https://$REPLIT_EXPO_DEV_DOMAIN
REACT_NATIVE_PACKAGER_HOSTNAME=$REPLIT_DEV_DOMAIN

Estos vars son solo para el Replit preview (modo --localhost). Si se usan con --tunnel, sobreescriben la URL del servidor con el dominio Replit en vez del URL ngrok → el dev client recibe la URL incorrecta. Estas vars no están en el entorno global (confirmado), así que solo afectan si se copia el script del workflow.

Fix exacto
No hay que cambiar metro.config.js. El fix es de invocación:

Ejecutar el tunnel desde dentro de artifacts/mobile/, sin las vars del Replit preview:

cd /home/runner/workspace/artifacts/mobile
pnpm exec expo start --dev-client --tunnel --clear

Esto:

Hace que expo start encuentre artifacts/mobile/app.json (el correcto, con bundleIdentifier: com.resonancia.app)
Establece projectRoot = /home/runner/workspace/artifacts/mobile
Usa el metro.config.js con todos los workarounds correctos
Establece el tunnel ngrok sin interferencia de las vars de Replit
El workflow actual (--localhost + vars Replit) es para el preview de Replit. Para el teléfono físico, son dos modos separados que no pueden coexistir en el mismo proceso.
